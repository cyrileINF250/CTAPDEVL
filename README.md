Screen rotation destroys and recreates the Activity (onPause -> onStop -> onSaveInstanceState -> onDestroy, then onCreate -> onStart -> onResume), saving and restoring the log through onSaveInstanceState and savedInstanceState. Pressing the Home button sends the Activity to the background without destroying it (onPause -> onStop -> onSaveInstanceState), so returning resumes the same instance via onStart -> onResume without calling onCreate again.
Filtering Logcat by LabCheckLifecycle confirmed the exact callback order across backgrounding, rotation, and manual check-in clicks once recordEvent("onSaveInstanceState") was added.
